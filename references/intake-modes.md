# 双输入模式与安全存盘规约 (Intake Modes)

## 一、 模式一：文件直传模式 (Direct File Ingestion)

当用户通过拖拽、附件、绝对路径发送物理文件（`.docx` / `.pptx` / `.xlsx` / `.pdf` / `.mp4` / `.wav` / `.png` / `.md`）时，严格执行以下流程：

### 1. 零篡改铁律 (Zero-Tampering Invariant)
* **严禁修改正文**：未经用户明确要求（如“帮我改写这篇脚本”），严禁增删改查文件内部任何文字、段落、格式、排版或代码；
* **二进制文件纯物理移动**：使用原生 `shutil.copy2` 或 `cp -p` 保留原始时间戳与权限；
* **哈希防覆盖保护**：
  * 入库前先计算待存文件的 MD5；
  * 若目标路径已存在同名文件且 MD5 一致，提示用户文件已存在，无需重复导入；
  * 若同名但 MD5 不一致，**严禁静默覆盖**，自动添加自然语义标识或日期（如 `脚本_戒烟篇.docx`），保证历史数据零灭失。

### 2. 二进制文件伴生索引机制 (Sidecar Note)
* Office 与 PDF 文件由于无法直接内嵌 YAML，若属于核心交付物，在同级目录建立轻量伴生 Markdown 索引（或直接在对应看板中以 `[[xxx.docx]]` 挂载并配置标签），确保其能被 Obsidian 标签面板与全局搜索秒级检索。

## 二、 模式二：内容整理生成模式 (Content Synthesis)

当用户在聊天框发送散碎文字、语音转文字、头脑风暴或微信公众号文章链接时，执行专业级整理：

### 1. 业务体裁提炼标准
* **口播脚本**：必须贯彻《口播创作8大底层原则》：
  * 黄金前 3 秒直入冲突痛点（0秒废话）；
  * 保持 300~450 字，预计时长 60~85 秒；
  * 强化人话与口语质感，剔除书面 AI 味；
  * 标注重点停顿与重音提示。
* **AI 短剧灵感**：
  * 提炼主角小传（童年、欲望、软肋、反差点）；
  * 提炼前 3 秒冲突爆发点与反转悬念钩子；
  * 产出符合画面光影、镜头语言（如阿莱质感、景深）的生图生视频 Prompt。
* **企业 AI 交付物料**：
  * 按照“客户背景 ➔ 痛点卡点 ➔ 数字化解决方案 ➔ 落地步骤 ➔ 交付台账”结构化落盘。
* **临时速记**：
  * 提取核心观点，保留原始记录日期。

### 2. 命名与格式
* 采用自然语义命名，不堆砌死板后缀；
* 调用 `obsidian-markdown` 官方语法规范，生成干净的 YAML Frontmatter、Wikilinks 与 Callout。
